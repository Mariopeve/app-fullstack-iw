Roadmap:
Nos reuniremos una vez a la semana, donde pondremos en común los avances que hayamos hecho al igual que las dificultades encontradas. En el propio sprint cada uno decidirá qué es en lo que va a enfocarse durante el siguiente sprint. Además presentaremos un feedback del trabajo de los demás compañeros. En principio el primer sprint será para acordar la metodología de trabajo, un diseño general y de las funcionalidades básicas.

Eventos de Scrum:
Al principio haremos reuniones semanales de 30 minutos en la que cada uno expondrá su trabajo y el resto del equipo serán los encargados de revisarlo y darle un feedback. Si vemos que el desarrollo del proyecto es bueno podemos bajar la frecuencia de las reuniones a una cada dos semanas.

Modelo de trabajo:
Cada integrante del equipo trabajará en distintas ramas, las cuales serán de responsabilidad única, las cuales serán añadidas al main cuando se acepte un Pull Request obligatorio, evitando que código no revisado por otro compañero sea fusionado con el main. Usaremos las nomenclaturas de feat: para una función, fix: para arreglar una función, docs: para añadir documentación y refactor: para reestructurar alguna función. La gestión de versiones se hará mediante los commits, permitiendo hacer rollback en caso de ser necesario volver a una versión anterior estable.

Definición del done:
Para dar por terminada una tarea, exigiremos que esté implementada, probada, tanto por pruebas unitarias como globales, revisada por otro compañero del equipo, integrada en la rama main y sin errores y documentada correctamente añadiendo la información necesaria al manual de usuario.

Acuerdos del equipo:
Nos comunicaremos mediante WhatsApp y Google Meet, las herramientas con las que desarrollaremos el proyecto serán Visual Studio Code como entorno de trabajo, GitHub para el control de versiones, Java 21 y Spring Boot 4, Vaadin 25, Apache Maven y AWS para desplegar servicios en la nube. Para la resolución de conflictos pondremos en común ambas versiones y decidiremos entre los miembros del equipo. Usaremos Gemini en el caso de que necesitemos ayuda por parte de la IA, debido a que tenemos la versión de pago.
